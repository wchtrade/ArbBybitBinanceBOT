# ArbScreenerBot — скрининг арбитражных монет (Binance / KuCoin / HTX)

## Назначение

Это НЕ боевой торговый бот. Это инструмент разведки: прогоняет широкий
список монет (115 шт) через три биржи, копит статистику по каждой монете
(сколько раз давала сигнал, средняя/лучшая маржа, симулированный P&L) —
и по итогам нескольких дней работы через `/leaderboard` ты видишь, какие
монеты реально стабильно дают спред между этими тремя площадками. Именно
эти монеты потом переносим в отдельного боевого бота (по образцу
`arb_bot_final.py`) для реальной торговли с настоящими API-ключами.

Бот **не отправляет реальных ордеров** ни в каком режиме — это часть
дизайна, не недоработка: на этапе скрининга деньги трогать не нужно.

## Мультивалютный арбитраж (новое)

Раньше сравнивались только пары `COIN/USDT`. Теперь бот дополнительно
проверяет `COIN/BTC` и `COIN/ETH` между теми же тремя биржами — это
независимые от USDT-рынка стаканы, там тоже бывает рассинхрон, которого
нет в парах к USDT.

**Как считается лот и прибыль для не-USDT пар.** Лот всегда размеряется
в USDT-эквиваленте (`LOT_USDT`, по умолчанию 100) — для пары `ETH/BTC`
бот сам переводит эту сумму в эквивалент в BTC по текущему курсу
`BTC/USDT` (который и так есть в данных, поскольку BTC сам торгуется в
основном списке). Прибыль по такой сделке реализуется в BTC (или ETH), а
не в USDT напрямую.

**Автоконвертация прибыли в USDT.** Прибыль по не-USDT парам копится в
отдельном балансе по каждой валюте (`currency_balances`). Как только
эквивалент в USDT достигает порога `CONVERT_THRESHOLD_USDT` (по
умолчанию 20 USDT) — бот "конвертирует" накопленное по текущему курсу:
прибавляет к реализованному P&L, сбрасывает счётчик, шлёт уведомление в
чат и пишет в `/balances`. До этого момента прибыль считается
"незавершённой" и НЕ учитывается в стоп-лоссе — только реализованный
(уже сконвертированный) P&L считается против лимита `-50 USDT`.

## Биржи

- **Binance** — через `data-api.binance.vision` (обходит блокировку 451 на облачных IP типа Railway)
- **KuCoin** — прямой публичный API
- **HTX** (бывш. Huobi) — прямой публичный API
- **Bybit намеренно не включён** — подтверждённо блокирует облачные IP через CloudFront (403), без VPS/прокси не лечится

## Монеты (115 шт, категориями)

Топ-майоры, L2/новые сети, DeFi, AI-токены, мем-коины, игры/NFT, другие
L1, инфраструктура/индексация, разное — полный список в начале файла
`arb_screener_bot.py`, переменная `SYMBOLS`. Часть монет может
отсутствовать на одной-двух биржах — это нормально, такие просто не
попадут в сравнение (нужно данные минимум с 2 бирж одновременно).

## Параметры симуляции

| Параметр | Значение | Переменная |
|---|---|---|
| Стартовый капитал (справочно) | 10 000 USDT | `START_CAPITAL` |
| Лот / шаг сделки (USDT-эквивалент) | 100 USDT | `LOT_USDT` |
| Стоп-лосс (по реализованному P&L) | -50 USDT | `STOP_LOSS_USDT` |
| Порог маржи для сигнала | 0.15% | `MIN_PROFIT_PCT` |
| Порог автоконвертации BTC/ETH→USDT | 20 USDT | `CONVERT_THRESHOLD_USDT` |
| Лимит сделок в минуту | 5 | `MAX_TRADES_PER_MIN` |

Стоп-лосс: при накопленном РЕАЛИЗОВАННОМ P&L ≤ -50 USDT торговля (запись
новых сделок) автоматически приостанавливается, сигналы дальше идут
только справочно — включить обратно можно только командой `/resume`,
никакого автосброса по таймеру.

## Пауза и маршруты (новое)

**`/pause`** — ручная пауза, не дожидаясь стоп-лосса. Сканирование и
показ сигналов продолжаются как обычно (это не тратит лишних ресурсов —
сами запросы к биржам дешёвые), но новые сделки перестают писаться в
P&L. Использует ту же инфраструктуру, что и автопауза по стоп-лоссу —
`/resume` снимает и ту, и другую одинаково. В `/stats` теперь видно не
просто "пауза активна", а конкретную причину (ручная или стоп-лосс).

**`/routes`** — рейтинг маршрутов биржа→биржа (например, `Binance →
KuCoin`), независимо от монеты: сколько раз этот маршрут давал сигнал,
сколько сделок, суммарный P&L, лучшая замеченная маржа и примеры монет,
на которых маршрут сработал. Отвечает на вопрос "между какими биржами
арбитраж встречается чаще всего" — иногда важнее самой монеты, потому
что показывает, где вообще стоит держать капитал прежде всего.

## Команды

```
/start          — запустить мониторинг в этом чате
/scan           — скан всех 115 монет × 3 валют котировки × 3 биржи прямо сейчас
/top            — топ-20 пар по спреду (даже ниже порога — для разведки)
/prices SYMBOL  — bid/ask по конкретной монете на всех биржах и валютах котировки
/exchanges      — диагностика: сколько пар реально отдаёт каждая биржа
/leaderboard    — рейтинг МОНЕТ-кандидатов (агрегат по всем валютам котировки)
/pairs          — рейтинг конкретных СВЯЗОК монета/валюта (через что именно нашёлся арбитраж)
/routes         — рейтинг МАРШРУТОВ биржа→биржа (где арбитраж чаще всего, независимо от монеты)
/balances       — накопленные BTC/ETH, ожидающие автоконвертации, + журнал конвертаций
/stats          — общая статистика сессии (реализованный P&L отдельно от ожидающего, причина паузы)
/history        — последние 10 сделок
/pause          — приостановить торговлю вручную
/resume         — снять паузу (ручную или после стоп-лосса)
/setprofit 0.15 — изменить порог маржи
/setlot 100     — изменить размер лота (в USDT-эквиваленте)
```

`/leaderboard` показывает, какая монета в принципе работает (не важно,
через какую валюту). `/pairs` — детализация: например, "SOL" может быть
в лидерборде за счёт находок в SOL/BTC, а не SOL/USDT — это видно только
в `/pairs`. `/routes` добавляет третье измерение — между какими именно
биржами это чаще происходит. Смотри все три раз в день-два, не в первый
час работы — статистика на коротком окне ненадёжна (см. историю: за
один вечер выбрали 5 монет, на следующий день 4 из них замолчали).

## Деплой (Railway, как остальные боты)

1. Файлы: `arb_screener_bot.py`, `requirements.txt`, `.python-version`.
2. Start Command: `python arb_screener_bot.py` (или переименуй в `main.py`,
   если так настроено в Railway — см. историю с прошлыми деплоями, где
   Railway продолжал запускать старый файл по забытому имени в Start Command).
3. Variables → `ARB_BOT_TOKEN` обязателен, остальное по желанию.
4. После деплоя сразу `/exchanges` — проверить, что все 3 биржи живые
   (Binance/KuCoin/HTX должны показать не 0 пар, с разбивкой по USDT/BTC/ETH).

## Что дальше

Дай боту поработать минимум 2-3 дня (лучше неделю) без вмешательства,
периодически проверяя `/leaderboard` и `/pairs`. Монеты (и конкретные
связки), которые стабильно появляются в топе несколько дней подряд, а не
разово за один вечер — кандидаты на перенос в боевого бота с реальными
API-ключами.
