# ArbBybitBinanceBOT v2 — СХЕМА АРБ (крипто-плечо)

USDT → COIN → USDT round-trip арбитраж на споте между Binance и Bybit.
Монеты по умолчанию: BTC, ETH, SOL, XRP, DOGE, TRX, ADA, LTC (`ARB_COINS`).

## Как считается сделка

1. Продаёшь COIN за USDT на бирже X по цене **bid** (нужен запас COIN там заранее).
2. Покупаешь COIN за USDT на бирже Y по цене **ask** (нужен запас USDT там заранее).
3. Профит, если bid(X) > ask(Y), за вычетом `ARB_FEE_PCT` (запас на комиссии обеих ног).

Это **модель без переводов между биржами в моменте сделки** — CEX-переводы
занимают время и не годятся для арбитража на секундных спредах. Вместо
этого COIN и USDT держатся предварительно на обеих площадках. Со
временем COIN будет накапливаться на бирже, где ты покупаешь, и
истощаться там, где продаёшь — команда `/inventory` показывает это
смещение, чтобы ты вручную периодически переводил монету обратно.
Автоматических переводов между биржами бот не делает — это осознанно,
ради безопасности (перевод не туда/не тому — необратимая потеря денег).

## Режимы

- **SIMULATION** (по умолчанию) — виртуальный расчёт профита, без реальных ордеров.
- **REAL** — в отличие от P2P-версии бота, у спота есть нормальный
  подписанный API, поэтому REAL **реально размещает MARKET-ордера** на
  обеих биржах (продажа на одной, покупка на другой). Включается только
  если одновременно:
  - заданы `BINANCE_API_KEY` / `BINANCE_API_SECRET`,
  - заданы `BYBIT_API_KEY` / `BYBIT_API_SECRET`,
  - `ARB_CONFIRM_REAL=YES`.

  Если чего-то не хватает, бот в режиме REAL присылает сигнал только
  справочно, ничего не исполняя — случайно "включить реальные деньги"
  через один `/mode real` не получится.

### Безопасность API-ключей

- Права ключей — **только спот-торговля**. Право на вывод средств — **выключить**.
- По возможности включить IP-whitelist на адрес сервера Railway.
- Начинать с малого `ARB_TRADE_USDT` (20–50) и проверить на паре сделок,
  прежде чем увеличивать размер.
- Перед первым включением REAL стоит прогнать бота в SIMULATION хотя бы
  день-два и свериться с `/rates`, что найденные спреды реальны, а не
  артефакт задержки/лага между двумя тикерами.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ARB_BOT_TOKEN` | токен Telegram-бота | обязателен |
| `ARB_CHAT_ID` | chat_id (можно не задавать — определится после `/start`) | — |
| `ARB_MODE` | `SIMULATION` или `REAL` | `SIMULATION` |
| `ARB_COINS` | список монет через запятую | `BTC,ETH,SOL,XRP,DOGE,TRX,ADA,LTC` |
| `ARB_TRADE_USDT` | размер сделки за круг, USDT | `30` |
| `ARB_MIN_MARGIN` | порог маржи для сигнала, % | `0.35` |
| `ARB_FEE_PCT` | запас на комиссии обеих ног, % | `0.20` |
| `ARB_SCAN_INTERVAL` | интервал мониторинга, сек | `60` |
| `BINANCE_API_KEY` / `BINANCE_API_SECRET` | ключи Binance (спот-трейд, без вывода) | нужны только для REAL |
| `BYBIT_API_KEY` / `BYBIT_API_SECRET` | ключи Bybit (спот-трейд, без вывода) | нужны только для REAL |
| `ARB_CONFIRM_REAL` | `YES` — явное подтверждение на реальную торговлю | — |

## Команды бота

```
/start     — запустить мониторинг в этом чате
/scan      — сканировать все монеты сейчас
/rates     — текущие bid/ask по всем монетам и биржам
/mode      — показать/переключить режим (simulation|real)
/balance   — виртуальный P&L (SIMULATION) + лог реальных сделок
/inventory — накопленный сдвиг монет между биржами (когда пора ребалансировать)
/reset     — сбросить симуляцию и счётчик инвентаря
/help      — список команд
```

## Деплой (Railway + GitHub, как остальные боты)

1. Залить `arb_usdt_crypto_bot.py`, `requirements.txt`, `.python-version` в репозиторий.
2. Railway → New Project → Deploy from GitHub repo.
3. Variables → `ARB_BOT_TOKEN` обязателен; остальные — по необходимости.
4. Start Command: `python arb_usdt_crypto_bot.py`.
5. Состояние (P&L симуляции, лог реальных сделок, инвентарь) пишется в
   `arb_state_v2.json` в рабочей директории — без Railway volume теряется
   при редеплое. Для устойчивости — подключить volume и
   `ARB_STATE_FILE=/data/arb_state_v2.json`.
